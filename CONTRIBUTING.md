# Contributing to TwinStack

First, thank you for being part of the **Vibecoder** community. We build in public because we believe the best software is shaped by those who observe its birth.

## 👥 How to Contribute

### 1. Forking the Project
If you have an idea for a feature or a UI refinement:
- Click the **Fork** button on top of the repository.
- Create a new branch: `vibecoder/feature-name` or `vibecoder/fix-name`.

### 2. Branch Naming Conventions
- `feature/*`: New functional capabilities.
- `ui/*`: Visual improvements or styling.
- `refactor/*`: Code quality improvements.
- `docs/*`: Documentation updates.

### 3. Coding Standards
- **Minimalism**: If it doesn't add immediate value, don't ship it.
- **Type Safety**: Use TypeScript interfaces for all data structures.
- **Tailwind Only**: No external CSS files. Use semantic tailwind classes.
- **Animation**: Use Framer Motion (`motion/react`) for interaction feedback.

### 4. Pull Request Structure
Every PR must include:
- **Title**: Clear and concise.
- **Summary**: What changed and why?
- **Impact**: Does this affect mobile? Is it a breaking change?
- **Screenshot**: Required for all UI changes.

### 5. Review Process
The **Architect** reviews all PRs for product fit. The **Builder** reviews for performance and code quality.
